# TapHabit 网页统计台

同一份习惯数据的桌面版：**读的是小程序导出的那份 JSON**，重点放在统计上，
打卡只留了「记一笔」和「删一条」。

统计页四张图，共用同一片时间窗口（日 30 天 / 周 26 周 / 月 12 个月 / 年 5 年）：

| 图 | 看什么 |
| --- | --- |
| 打卡趋势（折线） | 全部习惯合计，每（天/周/月/年）打了多少次 |
| 习惯对比（柱状） | 各习惯在同一区间里的次数，从多到少排 |
| 两习惯对比（折线） | 挑两个习惯，看各自每一格的次数 —— 第二条走虚线，颜色接近也分得开 |
| 打卡占比（环比） | 各习惯占这一区间总次数的比例；第 7 名往后并成「其他」 |

跨习惯一律**只比次数**：各习惯单位不同（次 / 分钟 / 页），数值加起来没有意义。
单个习惯的详情弹窗里才看数值。

右栏是 **AI 分析**：把当前区间的统计摘要发给 AI，让它点评 + 给建议。

## AI 分析

点开右栏的「接入设置」，选一个服务商、粘上自己的 API Key 就能用。
预设里有云端的（DeepSeek / OpenAI / Claude / 通义 / 智谱 / 月之暗面 / 硅基流动），
也有跑在**你自己机器上**的（Ollama / LM Studio，连 Key 都不用）。想全本地就选后者。

### 它发出去的是什么

**只发汇总，不发原始记录**：区间起止、总次数、打卡天数、完成率、
各习惯的次数 / 活跃天数 / 完成率 / 连续天数 / 最长连续，以及每格的趋势。
几 KB 封顶。一条打卡记录都不会离开这台机器 —— 记录总数、备注、每条的时间戳都不在提示词里。

### Key 存在哪

存在浏览器的 **IndexedDB** 里，走的是一个**独立于打卡数据**的存储格。

这一条是刻意的：打卡数据会被导出成 JSON、会被备份、可能被丢进 git、还会回流到小程序，
Key 要是混在里面就等于一路泄露。分开存之后，**导出的文件里连这几个字段都没有**
（`exportText()` 只挑 `app / schema / exportedAt / habits / records / settings`）。

代价是换台机器、换个浏览器要重填一次 —— 这本就该重填。

### 本地模型连不上？

多半是 CORS。页面从 `file://` 打开时，浏览器发出去的 `Origin` 是 `null`，会被本地服务拒掉：

- **Ollama**：先设环境变量 `OLLAMA_ORIGINS=*` 再启动（Windows 上在「系统环境变量」里加）。
- **LM Studio**：在 Developer / Server 设置里打开 CORS 开关。
- 或者干脆别用 `file://`：在项目目录里跑 `python -m http.server 8000`，
  再用 `http://localhost:8000/html/` 打开本页，`Origin` 就是正常的。

云端服务商（DeepSeek / OpenAI / Claude 等）一般允许浏览器直连，`file://` 下也能用。

### 支持的协议

| 协议 | 端点 | 谁在用 |
| --- | --- | --- |
| OpenAI 兼容 | `POST {base}/chat/completions` | OpenAI、DeepSeek、通义、智谱、硅基流动、One-API 自建、LM Studio、vLLM |
| Anthropic | `POST {base}/v1/messages` | Claude（浏览器直连要带 `anthropic-dangerous-direct-browser-access`） |
| Ollama | `POST {base}/api/chat` | 本机 Ollama |

自定义服务商选「自定义（OpenAI 兼容）」，把 base（要含版本路径，比如 `.../v1`）和模型名填进去即可。

## 怎么打开

这个文件夹必须**待在项目里**（它要 `../utils/date.js` 和 `../utils/stats.js`），
单独拷出去是不行的。直接双击 `html/index.html` 即可，
不需要装任何东西，也不需要起服务器。

## 数据放在哪

两种存法，同时进行：

| 存法 | 位置 | 说明 |
| --- | --- | --- |
| 本地文件 | 你绑定的那个 `.json`（建议就放 `html/` 里） | 每次改动自动写回，**没有容量上限**，磁盘能放多少就多少 |
| 浏览器库 | IndexedDB | 兜底。没绑文件时数据也丢不了 |

浏览器不许网页「不问自取」地写本地文件，所以**第一次要你点一下授权**：

- **绑定新文件** —— 新建一个空的 `taphabit-data.json` 并连上。
- **打开已有文件** —— 挑一个已经存在的（比如小程序导出的那份），连上就地更新。
- **重新连接** —— 关掉页面、隔天再开时，浏览器把授权收了，点这个补一次。
- **重新读取文件** —— 文件被别的程序改过（比如小程序又打了几天卡），从文件重读。

授权状态记在浏览器里（IndexedDB），下次打开如果还有效就自动连上。

## 和小程序的兼容

- 文件格式**完全一致**：`{ app: 'TapHabit', schema: 1, exportedAt, habits, records, settings }`，
  `records` 按习惯分桶，短名 `d / v / n / t` 与小程序一模一样。
- 小程序的「存储管理 → 导出」拿到的 JSON 可以直接在这里导入；
  这边的「复制 JSON」也能直接粘进小程序的导入框，两边来回搬不会掉数据。
- 导入会**整份覆盖**当前数据，导之前先备份。
- 网页版**没有**自定义主题（只做深浅两套）与背景图，导入时和 `utils/storage.js`
  一样会把 `customTheme.image` 和每个预设的 `image` 抹掉。
- 网页版**允许补记过去的日期**（小程序里只能记当天）—— 桌面端多半就是拿来补账的。
- 网页版**不做** 95% 自动清理：容量按磁盘走，没有那个问题。

## 日期与统计是同一份实现

`utils/date.js` 和 `utils/stats.js` 是 CommonJS 模块，浏览器里没有 `module` / `require`。
`index.html` 末尾那几行给它们搭了个最小的运行环境，于是：

- 时间窗口（日 30 / 周 26 / 月 12 / 年 5）、连续天数、热力等级、图表粒度，
  网页和小程序算出来的**永远是一个口径**；
- 不会出现「改了小程序忘了改网页」这种两份实现迟早会犯的错。

代价就是上面那句：这个文件夹不能搬走。

## 滚动

原则：**卡片里的东西能缩就缩，不去开第二层滚动条**；只有「缩了就不好看」
或者「它本来就是一块输出」的地方才滚。

| 位置 | 怎么办 |
| --- | --- |
| 图表的画布 | 宽度就是卡片宽度，格子密了把每格压窄、标签抽稀（`labelStep`）——不滚 |
| 热力图 | **滚**（横向）。五年历史压缩到一屏会把每周压成几个像素，那样就看不出是日历了 |
| 排行榜 | 取消高度上限，跟着页面滚；环图图例条数由 `PIE_TOP` 封顶 |
| AI 结果框 | **滚**（`min(38vh, 380px)`）。它是输出，一两千字顶得整页很长，读起来得一直往下翻 |
| AI 问题框 | **滚**（88–160px）。免得一个问题把右栏撑高 |
| 弹窗 | 滚，且保持在屏幕内 |

由此右栏**不做** `position: sticky`：它从「接入设置」展开到结果框能长到七八百像素，
粘住的话底下的部分永远滚不到底，结果框自己那条滚动条也跟着够不着。

滚动条本身在 `styles.css` 里统一收细、颜色跟着主题走（`--scroll-thumb`），
Firefox 走 `scrollbar-width`，其余走 `::-webkit-scrollbar`。

## 浏览器要求

写本地文件用的是 **File System Access API**，目前只有 **Chrome / Edge** 有。
Firefox / Safari 打开也**能用**，只是「绑定文件」那几个按钮不生效 ——
退化成「下载 JSON / 导入 JSON」手动搬运，数据存在 IndexedDB 里。

## 文件

| 文件 | 干什么的 |
| --- | --- |
| `index.html` | 页面骨架 + 那两个 CommonJS 模块的加载器 |
| `styles.css` | 深浅两套配色，变量名沿用小程序那一套 |
| `store.js` | 数据层：读写、校验、导入导出、IndexedDB + 文件双写；AI 配置另存一格 |
| `ai.js` | 三种 AI 协议、提示词拼装（不碰 DOM，Key 不进数据文件） |
| `charts.js` | 折线 / 柱状 / 环比三张图，Canvas 2D 手写，颜色从 CSS 变量读 |
| `app.js` | 渲染与交互：统计页、习惯页、数据页、两个弹窗 |
